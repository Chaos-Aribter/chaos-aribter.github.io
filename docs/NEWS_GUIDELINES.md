# CACX 新闻编辑与开发规范

本规范依据用户提供的「后台字段对照标注」「新闻文稿填写手册」及补充截图整理，适用于新闻稿件、首页新闻展示、Banner、列表、详情页与相关样式。每次执行先阅读，涉及的条款须在交付前自检。更新日期：2026-09-07。

## 1. 规则口径与实施边界

- 继承本站黑底、米白文字、红色强调、细边框和栅格布局，不引入另一套视觉体系。
- 原型中的红框、字段编号、编辑说明和工具栏是设计标注，不渲染到公开页面。
- 图片像素尺寸是素材规格，不是页面固定宽度。所有图片必须适配容器。
- 规范是目标契约，不代表后台、Markdown 渲染、自动裁图、定时发布或浏览统计已经实现。不得把占位值或演示内容冒充生产数据。
- 默认本地实现与验证，等待用户验收并明确授权后再推送、发布。

### 原始材料中的差异

1. 字段对照图写「上传一张横图自动裁出五种尺寸」，填写手册则要求独立题图和封面图。采用后者作为当前交稿规范：题图和封面图分别提供；只有确认自动裁切功能已实现且裁切结果验收通过，才允许单图替代。不能默认宣称已有自动裁图功能。
2. 首屏 Banner 的「首页滚动」和军团数据上方的「最新三条」是两个独立区域。最新三条按已发布新闻的日期倒序取最多三条，不受首页滚动开关控制。
3. 主体字段表将发布日期标为 A3/D4/E3；右侧索引另将 B3 明确为卡片日期。实现时日期同时映射 A3、B3、D4、E3。
4. 截图索引未定义 E2，不自行补造字段编号。

## 2. 新闻稿件字段

| 字段 | 要求 | 内容约束 | 展示位置 |
| --- | --- | --- | --- |
| 标题 | 必填 | 中文不超过 60 字；英文不超过 80 字；说明核心信息 | A2、B2、C2、D2、E1、E4 |
| 副标题／摘要／导语 | 必填 | 中文不超过 120 字，一句话说明新闻要传达什么 | C3、D3、E5 |
| 题图 | 必填 | 详情顶部横图，规格见图片表 | E6 |
| 封面图 | 必填 | 卡片缩略图；其他位置使用适当裁切版本 | A1、B1、C1、D1 |
| 正文 | 必填 | Markdown；建议 3–6 段、1–4 个小标题；至少 600 字；正文配图最多 3 张 | E7a–E7e |
| 发布日期 | 必填 | YYYY-MM-DD；编辑默认可为当天 | A3、B3、D4、E3 |
| 来源／作者 | 选填 | 自由文本；留空显示 FLEET COMMAND | E3 |
| 是否置顶 | 开关 | 同一时间最多一篇 | C1–C4；Banner 可作兜底 |
| 是否首页滚动 | 开关 | 与置顶独立；建议最多 3 篇 | A1–A4 |

卡片标题最多显示两行并截断；详情页大标题必须完整显示并自然换行。面包屑末级可截断，但保留完整可访问名称。截断仅影响展示，不修改原始数据。

未来日期用于定时发布时，必须有经过验证的调度／重新构建机制；仅写入未来日期不等于实现定时发布。未到发布时间的内容不应提前进入公开列表、最新三条或 Banner。

## 4. 首页、置顶、列表与轮播

- 首页最新新闻位放在军团数据上方，按发布日期倒序取最新三条；不足三条只显示实际数量。
- 点击卡片进入对应详情；「查看全部新闻」进入 `/news`。
- 置顶最多一篇，选中新置顶时替换旧置顶；不要产生多个焦点位。
- 「置顶」与「首页滚动」独立：只启用首页滚动不代表列表置顶；只置顶可在未配置轮播新闻时作为 Banner 新闻兜底。
- 没有配置首页滚动新闻时使用置顶新闻兜底；两者均无时，不显示虚构的置顶内容。
- 新闻列表按发布日期倒序。当前每页四条普通新闻，焦点新闻不重复计入普通列表；超过一页才显示分页。
- 分页包含页码、上一页、下一页、当前页状态；首尾边界禁用；翻页后定位到列表开头并保持键盘可操作。

### Banner 字段

| 字段 | 要求 | 规则 |
| --- | --- | --- |
| 帧类型 | 必填 | 新闻帧、品牌帧、活动帧三选一 |
| 关联新闻 | 新闻帧必填 | 选已发布文章，自动带出封面、标签、日期、标题和链接 |
| 排序 | 必填 | 数字升序决定帧顺序，对应 A4 |
| 背景图 | 品牌／活动帧必填 | 1440×640；新闻帧可取关联文章封面作为背景 |
| 主标题上／下行 | 品牌／活动帧需要 | 上行米白实心；下行可选描边空心效果 |
| 徽标／标语／链接 | 选填 | 徽标在标题上方，标语在标题下方红条与说明文字区域，链接为整帧跳转 |
| 生效时段 | 活动帧需要 | 控制活动展示窗口，需实际调度支持 |

## 5. 正文 Markdown 与渲染

| 编辑输入 | 渲染约定 |
| --- | --- |
| 普通段落 | Noto Sans SC，正文基准 15px／26px 行高 |
| `## 小标题` | 左侧 3px 红条，Noto Sans SC Bold，基准 20px |
| `> 引用文字` | 左侧 4px 红条、米色斜体、浅灰底 |
| `![描述](图片路径)` | 正文配图，填满正文容器但不超出；原型内容宽度 1292px 不作为手机固定宽度 |
| 图片紧接下一行的 `*图注文字*` | 附图斜体小字图注，紧随图片 |
| `- 要点` | 红色圆点列表，适合战损与重点信息 |

正文至少三个段落和一个小标题。战报、简报、公告模板可组织不同内容，但必须共享上述排版规则。

正文禁止表格（改用列表）、内嵌视频（改用截图）、外链、HTML 标签、内联 CSS、自定义颜色及字体加粗控制。这里的限制针对编辑提交的正文，不禁止系统导航、图片资源引用或本规范文档中的表格。渲染器应明确校验／过滤不支持内容，不能执行原始 HTML、脚本或样式；不要无提示吞掉内容。

## 6. 图片规范

| 用途 | 最小尺寸 | 建议尺寸 | 比例 | 格式 | 大小上限 |
| --- | --- | --- | --- | --- | --- |
| 题图：详情顶部 | 1292×532 | 1920×790 | 约 2.43:1 | PNG／JPG／WebP | 800 KB |
| 封面：卡片缩略 | 630×411 | 945×617 | 约 1.53:1 | PNG／JPG／WebP | 300 KB |
| Banner 新闻位封面 | 380×190 | 760×380 | 2:1 | PNG／JPG／WebP | 200 KB |
| 正文配图 | 1292×500 | 1920×1080 | 自适应 | PNG／JPG／WebP | 500 KB |
| 角色立绘／头像 | 200×200 | 按需 | 建议 1:1 | 透明背景 PNG | 150 KB |

图片统一填写 HTTP/HTTPS URL，不接收本地文件路径。URL 可包含查询参数，路径无需带图片扩展名；按响应内容检查格式、尺寸与体积。页面直接引用原始 URL，不下载到网站目录。正文普通外链仍禁止，图片 URL 是允许的资源引用。

源图片文件建议命名：`news-{文章ID}-{slot}.{ext}`（不强制远程 URL 命名）。

- 题图：`news-2026-0001-cover.jpg`
- 卡片封面：`news-2026-0001-thumb.jpg`
- 正文配图：`news-2026-0001-body-01.png`
- Banner 衍生图可使用 `banner` 槽位；需要实现并核验自动裁切时，保留原图和衍生图的关联。

裁切保持主体完整；不得拉伸变形。正文图保留内容比例，卡片与 Banner 可用经过确认的裁切。示例／占位素材在验收时明确说明，正式发稿必须换成对应文章素材。

## 7. 响应式与样式隔离

- 中文多行标题使用能容纳中文的正常行高，不复用首页大字的超紧行高与负间距。
- 不用固定像素位置拼接图文；采用 Grid／Flex，列设置可收缩宽度，图片不得通过高度和宽高比反推宽度挤压正文。
- 置顶图文在空间不足时改为上图下文；当前断点为 1000px。列表按容器可用宽度使用单列或双列瀑布流；首页最新新闻桌面三列、手机单列。
- 全局导航样式只能作用于主导航，不能污染详情翻页与分页。
- 导航、卡片、正文都不得横向溢出，控件支持键盘焦点；分页点击区域至少 44×44px。
- 涉及布局修改，检查 390px、884px、1280px、2560px 宽度，并关注断点前后。检查长标题、缺图、少量内容、多页内容、字体未加载情况。
- 不把测试通过等同于上线授权。构建通过后还需相关浏览器检查；若检查受阻，如实记录。

## 8. 系统负责的字段与能力

详情 slug、浏览量、上一篇／下一篇、相关阅读、分页及导航高亮由系统计算或开发一次性配置，编辑无需填写。实现时须保证：

- slug 唯一且稳定；浏览量无真实统计服务时不展示伪造数字。
- 上下篇依据发布顺序生成，不能固定指向同一条；末篇与首篇有明确边界行为。
- 相关阅读排除当前文章；链接对应真实页面。
- 静态部署场景需生成所有公开详情路径；新内容和定时发布需配合重新构建。
- 目前已存在的演示数据、手写正文不视为已完成此节要求。

## 9. 每次交付前自检

- [ ] 已读取本规范，标明本次涉及的规则；没有把编辑标注放入公开页面。
- [ ] 标题满足中文 60／英文 80 字限制，摘要不超过 120 字。
- [ ] 题图与封面已提供，尺寸、大小、比例、命名符合要求。
- [ ] 正文至少 600 字、三个段落、一个小标题，配图不超过三张。
- [ ] 发布日期合法，来源缺省处理正确，未来日期没有提前发布。
- [ ] 置顶唯一，首页滚动独立，首页最新三条排序与上限正确。
- [ ] 无错别字、正文外链、表格、内嵌视频及不支持的 HTML／CSS。
- [ ] 响应式检查无重叠、截断正文或横向溢出；卡片两行截断符合规则。
- [ ] 链接、上下篇、分页及数据为空或不足一页时的行为正确。
- [ ] 运行与本次修改相称的检查；记录尚未实现的规范、占位素材及受阻验证。
- [ ] 用户未授权发版时，没有推送或发布。

仅修改文档时，无需运行网站构建；检查字段完整、引用路径和规则冲突即可。纯局部开发不要求补齐无关功能，但不得宣称整体规范已经全部实现。

## 11. 本地稿件转换流程（2026-09-08）

- 当前采用 Markdown 模板与本地 `.bat` / `.sh` / macOS `.command` 脚本，无需编辑后台。操作见 `docs/LOCAL_NEWS_TOOL.md`，模板见 `templates/news-template.md`。
- 一份稿件生成共用数据，再构建详情、新闻总览和首页最新三条；仅本地输出 `out/`，不自动发布。
- 文章 ID 由稿件目录 YYYY-NNNN 固定，用作稳定 slug。置顶冲突时拒绝生成，由编辑将旧置顶改为否后重试。
- 首版不提供 Word 导入、自动裁图或自动定时构建。未来日期到期后需重新执行；首页滚动字段已保存，但首页 Banner 接入仍待实现。
- 当前阶段验收范围（2026-09-08）：先验证脚本生成后的本地运行；使用 `npm run preview:news` 预览静态产物。GitHub Pages 自动上传留待后续，不属于本次实施范围。

## 12. 新闻点击与元信息调整（2026-09-08）

- 置顶新闻整张卡片（图片、标题、摘要及阅读全文提示）使用一个链接进入详情，支持键盘聚焦与 Enter，不嵌套链接。
- 新闻置顶位、普通列表及详情均不展示阅读时长；日期和来源按各自位置保留。此要求覆盖先前的阅读时长展示约定。

## 13. 首页入口与加载体验（2026-09-19）

- 首页主导航必须显示新闻资讯入口，桌面与手机均可进入 `/news`。
- 首页、新闻列表与详情共用黑底红色进度条加载样式。首页等待舰船资源；新闻页等待字体与首屏图片，失败或超过 8 秒后放行，正文后续图片继续懒加载。
- 进入新闻板块、直接访问或刷新时加载一次；新闻列表、详情、上下篇之间的客户端跳转不重复播放加载动画，共享新闻布局保留加载完成状态。已缓存资源可快速完成，不为新闻额外加载首页舰船模型。

- 2026-09-19 补充：网站固定使用中文，移除首页 EN 语言切换按钮及切换逻辑。

## 14. 纯文字新闻展示（2026-09-19）

- `模板：text` 无需题图、封面；此例外覆盖上文图片必填要求。
- 首页最新新闻、总览普通卡片和置顶卡片、详情顶部均不渲染该模板的图片区域，不显示“图片待提供”、背景图或图片留白。
- 纯文字置顶卡片使用单列文字布局；普通卡片沿用现有响应式栅格，日期、标题、摘要和跳转行为按各展示位置保留。
- 图文模板继续保留图片及加载失败占位行为。

## 15. 新闻总览瀑布流（2026-09-19）

- 普通新闻采用两列瀑布流，卡片保持自然高度，不按行拉齐；按日期顺序将下一张放入当前较短列，同列上下保持 24px 间距，不留等高行空洞。
- 列表容器可用宽度不超过 680px 时使用单列；字体、图片和容器尺寸变化后重新排列。
- DOM 与键盘阅读顺序保持原有日期倒序；分页每页四条与置顶规则保持不变。首页最新三条不改为瀑布流。

## 16. 生成、验收与发布流程（2026-09-19）

- Windows 提供对应的 `test-news.bat` 与 `publish-news.bat`，与 `.sh` 共用 Node.js 流程、生成记录和发布检查；生成测试不自动发布。
- 提供 `test-news.sh`（生成并预览）与 `publish-news.sh`（提交、推送、触发现有 Pages 工作流）两个独立入口。教程见 `docs/NEWS_PUBLISH_TUTORIAL.md`。
- 生成不发布；运营完成本地验收后，手动运行发布脚本并输入 PUBLISH，确认本次全部待提交改动。
- 发布前验证成功构建记录、当前源码、产物与日期一致；变化后须重新生成和验收。只检查可用 `sh publish-news.sh --check`。
- 发布脚本仅接受当前仓库 origin 的 main 分支，校验远端基线，不强推、不自动合并、不创建空提交。推送成功只表示工作流触发，需到 Actions 确认部署结果。
- 第 11 节“自动上传留待后续”现由本节替代；代理本次仅制作脚本，不代表授权执行真实发布。
